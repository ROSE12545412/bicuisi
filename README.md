# 🦋 碧翠丝的禁书库

> 给 SillyTavern / **TauriTavern** 用的剧情引导扩展。
> 一位毒舌傲娇的大精灵住在你的屏幕角落，读你勾选的世界书，用一句「随口一提」把剧情往前推 —— 同时吐槽你的所作所为。

**不绑定任何特定作品。** 换一张卡、换一本世界书就换一套线索，Beatrice 只是个「话很多的引导者原型」。

## 两种模式正文头像卡片修复（r2026-10-12.36）

修复宿主已显示 display_text 时把纯文字误认为头像卡片已完成、撤掉美化的问题。人神与碧翠丝共享卡片恢复逻辑，各自保留头像与主题；只处理插件自己的引导段，保留正文、流式容器及其他插件显示。历史引导恢复不需要新 API 请求。

## 人神人设与公开台词补生成（r2026-10-12.35）

人神对抗正式接入独立 voidPersona 分段/覆盖提示，人设编辑不会影响贝蒂；不可覆盖的证据、因果、阶段规则放在人设之后。定位改成中立措辞，不再硬称贝蒂。启用的公开台词为空时不再报告投放成功或打开标题空壳；私有处理仍只提交一次，日志明确缺失。长按同楼时仅请求补生成公开引导/吐槽，schema 不含 proposals，拒绝额外提案，不改阴谋进度/历史；已有非空台词保留。补生成最多一次调用，不自动重试；失败仍可手动重试。补生成只提供当前正文、确认事实及公开人设，不发送私有账本。关闭的通道不强求台词；编辑/切卡/切聊天/请求期间配置改变会丢弃旧结果。此修复也可补 r34 已缓存的空台词，不用清空阴谋。

## 人神无适用原文分流（r2026-10-12.34）

人神对抗时，定位明确返回空数组或原文核查完成但没有适用来源，不再关闭整个观测：排除未通过原文及索引，仅向人神提供当前正文和确认事实。允许公开吐槽与有限私有计划；阴谋推进仍受原有证据、因果、反制机会、阶段及同楼幂等门槛。网络/中止/过期/解析错误仍停止，不当作无素材。碧翠丝原有严格原文门槛不变。诊断 stage 改为最近 API 请求，提示不再固定暗示推理耗尽。

## 无之空间长按重观测修复（r2026-10-12.33）

头像按住 2 秒：未成功提交的正文可重试失败阶段，已确认的事实观测可复用；成功处理（包括没有可推进事项）后不会再次调用阴谋模型推进同楼，而是恢复已保存的公开引导与吐槽。模型结果验证通过后，将账本、公开输出缓存及正文版本快照一起提交；展示失败可补投放，不再推进。缓存随编辑/swipe/删除回滚，最多保留 24 楼。旧版本已处理但未存公开输出的楼层提示缺少记录，绝不为补写而重复推进。忙碌时禁止叠加长按，有触发/失败/完成反馈；缓存和进度仍由酒馆聊天元数据保存，宿主落盘失败时只能保证当前内存幂等，不能保证崩溃后持久恢复。独立小字模式恢复已有消息，不重复追加。

## 阶段输出预算修复（r2026-10-12.32）

剧情定位不再固定 1200 tokens，使用所选阶段预设中「输出预算」与「结构化请求输出预算」的较大值（即使定位没有启用 schema）。原文适用性核查不再固定 3000 tokens，由客户端沿用该阶段预设预算。0 的结构化预算表示不额外抬高普通输出预算。HTTP 成功但非空答案 finish_reason=length 时明确显示阶段名称与实际预算，拒绝不完整内容并停止后续流程，不自动重试、不采用推理文本作答案。修改当前 API 不会改变已保存预设，请更新对应预设或将阶段设为当前 API。

## API 预设与四阶段分配（r2026-10-12.31）

API 页可保存最多 30 个本地预设，包含通道、连接配置 ID 或直连地址/Key/模型、温度、输出预算与超时。名称输入不打断焦点；选择不自动加载，需明确点击加载/更新，删除需二次确认。密钥仍是酒馆本地设置中的明文，不是加密保险箱；不要分享设置文件，公开错误报告不包含预设凭据。

事实观测、剧情定位、原文适用性核查、引导/吐槽/私有计划生成分别有独立预设下拉框，默认「当前 API 设置」，碧翠丝和人神共用阶段分配。四个环节并非启停开关，核查安全规则不变；世界书建池与连接测试仍使用当前 API。删除预设后引用它的阶段恢复当前 API；损坏配置中不存在的预设会明确报错而非暗中换连接。观测期间不能操作预设或阶段分配，外部更改也会使旧结果失效。

## 推理输出预算（r2026-10-12.30）

API 页新增「结构化请求输出预算」，作为事实/定位/人神等 json_schema 请求的最低输出额度，默认 8192，上限 32768；0 沿用各任务原额度。预算包含模型推理，增加额度可能增加费用和耗时，不保证模型必定生成答案。端点不支持 schema 的已有降级仍保留，预算不会因降级丢失；不新增自动重试，不将 reasoning_content 当最终答案。空答案且 finish_reason=length、存在推理时明确报「推理耗尽输出预算」。推理模型可尝试 16384 并适当增加超时，或使用非推理模型。

## 一键错误报告（r2026-10-12.29）

设置 → 诊断 → 📋 复制错误报告。报告保留最近 12 次辅助请求的时间、耗时、状态、调用次数、HTTP 状态、JSON 结构、内容长度、推理长度、finish_reason 与 token 统计；不包含地址、密钥、模型名、正文、世界书、请求提示或原始响应文本。记录仅当前页面内存保留，重启后先复现再复制。剪贴板不可用时可从只读文本框手动复制。HTTP/JSON/空内容错误分类与上层失败类别便于排查，报告不是原始响应转储，不会自动重试或额外调用 API。

## 角色设定指纹修复（r2026-10-12.28）

事实与人神观测不再比较整个宿主角色对象。酒馆 saveChat 会更新 date_last_chat，属于运行记录而非改卡；新的共享指纹仅覆盖头像身份、角色正文设定、系统/历史提示、问候、内置世界书、绑定书与深度提示等字段，排除聊天时间、大小、收藏等运行/展示数据。切卡和实际设定修改仍会拒绝旧响应。新增模拟保存时间变化与真实设定修改的回归测试。

## 正文收尾与取消诊断（r2026-10-12.27）

正文结束后先等待 1200ms 内容静止（最长等待 8 秒；仍在流式输出时不请求），再读取完成文本启动观测。停止操作可能先发结束事件再发停止事件：同一事件栈内的停止现在阻止辅助请求启动。忽略 quiet / impersonate / dry-run 的开始事件，避免非正文生成误取消观测。真正停止、切卡、新正文生成仍取消旧请求；日志记录取消来源，事实观测失败时列出变化楼层与消息数量，不输出正文。不能保证所有扩展的迟到改写都在等待窗口内；请求后正文再变化仍安全拒绝，请依据日志继续排查。

## 状态检查兼容修复（r2026-10-12.26）

修复保存聊天数据时，插件元数据槽被等值副本替换却误报过期的问题：事实观测与人神观测现在核对实际账本内容，并提交到当前槽位。真正的切卡、正文/分支变化、取消、配置变化和账本变更仍会拒绝旧响应；错误信息分别指出触发的检查，不包含正文或 API 密钥。此修复已用模拟保存路径复现并验证，实际酒馆若仍拒绝，可依据新的具体原因继续排查。

## 书签、共同日记与因果复盘（r2026-10-12.23）

设置中新增 **📚 书签与日记**：回看当前聊天已送达的提醒，收藏或取消书签，并按收藏筛选。世界书来源默认不显示，须先勾选本窗口的来源授权，再展开具体提醒；保存的是当时核查通过的原文快照（每条最多 12 个来源，单源最多 12000 字符），不是事后读取的新版世界书。

共同经历日记仅从有正文证据的 confirmed 中立事实生成，不把用户宣称、未来计划或世界书设定当作已经发生。碧翠丝后续台词可引用最近的有限日记，但不会改变善良底线或虚构亲密关系；人神不接收这段陪伴记忆。每个聊天最多 120 条提醒、80 条日记。编辑、删楼、滑动分支会撤销不再成立的记忆。可单条遗忘，或二次确认清空书签、日记、全部；已遗忘的同一证据不会下次打开又自动回来。

无之空间的 **人神对抗** 页有独立的「查看已结束阴谋的因果复盘」授权。只展示已失败、已解决、已致死的记录，包含原目的（计划）、阶段变化、已确认结果、关联前置事实、原文证据及用户回应机会；回应机会不等于反制成功，进行中的阴谋不展示。旧记录没有因果链时明确显示缺失，不补造过去。关闭窗口或切换模式会撤销来源与复盘的查看授权。语义识别仍依赖辅助模型，记录可追溯不等于模型必然判断正确。

## 事实账本与原文核对（r2026-10-12.21）

两种引导共用中立流程：**最新正文 → 有证据事实观测 → 轻索引定位 → 取回选中条目的完整实时原文 → 核对条件 → 引导/计划**。索引只找资料，不证明剧情事件已经发生；世界书说的是可能与设定，正文证明实际发生，计划仍是待尝试行动。

事实账本与阴谋账本独立。用户宣称只算尝试；事实引用原始楼层原句，区分 confirmed、unknown、contradicted，并记录角色知情依据。编辑、删楼、滑动分支回滚相关事实；未知条件不自动补齐。未选中的摘要不再注入作为兜底，读取失败不使用旧正文缓存替代正史。线索池页展示当前事实、来源及本次适用性判断。

**碧翠丝是绝对善良、真诚保护契约者选择的引导**，即使自定义人设也有不可覆盖的善意边界；不读取阴谋账本，不生成恶意误导或使徒计划。人神私有计划仅在无之空间对抗模式使用；专用规则书不进入任何模式的剧情索引。

每次新正文增加一次中立事实观测 API，同一楼层复用；有索引时还需定位一次。取回世界书原文后，另做一次独立适用性核查，只把通过的来源交给后续生成；未知、排除或没有有效依据的条目不会继续参与引导或计划。全部来源未通过时，本轮安全跳过。最后普通引导与吐槽仍来自同一次生成。对抗模式在相同事实/原文核对后另做对抗观测。**因此完整流程可能比旧版多一次 API 请求**。确切引用只能证明出处，无法数学证明模型的语义判断；保守核查可能拒绝合理同义改述，不宣称已彻底解决误判。

### r2026-10-12.22 修复要点

- 每次宿主事件刷新聊天上下文；请求与固定楼层、原文及滑动分支绑定。停止、切换聊天/角色、编辑正文后，迟到结果不能安装。普通观测统一单飞。
- 正文引导保存自己的显示层，保留已有翻译等覆盖；清除时只撤回自己拥有的内容，不重写第三方正文显示。
- 输入 API 密钥不再每字符重绘；模型列表迟到响应不会污染新的端点配置，也不擅自替换自定义模型名。公开诊断默认最小化，统一清理密钥、URL 参数和错误中的敏感值。
- 新提取的索引记录整本源书的 SHA-256 内容版本，原文、条目或相关元数据变化后需要重建；旧池没有版本基线时明确视为未验证，不伪造基线或静默删除已保存的池。
- API 超时会取消本次传输，保留温度 `0`，只对明确的接口签名不兼容尝试降级。宿主若无视取消信号，不能强制停止其服务器任务，但会丢弃迟到结果。

以上是程序与模拟宿主回归保障；不是对真实模型准确性或所有酒馆版本行为的保证。

## 线索池与角色卡

选好世界书后点击 **让 AI 通读世界书**。读取会覆盖全部非空条目的完整内容（长条目分段处理），不是只看标题或截取开头；筛选目标是故事会发生的事件、会登场的人物及其相关条件和阶段，纯格式指令或无剧情作用的资料不会自动充入池中。流程是 **阅读筛选 → 用户确认 → 提取入池**：阅读时显示进度条与当前第几次 API 调用；完成后展示完整候选列表，AI 选中的条目预先打勾，可展开阅读全文、改勾选。点击 **确认选择并开始提取** 才会启动提取，提取有独立的进度条和调用次数。确认前不会提取、保存或覆盖原池。首次自动阅读也必须打开世界书页面确认，不能绕过审核。分批读取和提取可能需要多次 API 请求，成本取决于书的长度；失败时保留已有池，不用不完整结果覆盖。

**自己挑** 与 AI 通读放在同一入口区域。池子可查看和修改，点击 **保存并绑定当前角色卡** 明确保存到当前卡，切换到其他卡不会混用。显式保存的池不会仅因时间到期被自动覆盖；换书或主动重建仍会更新。引导时先对照最近正文判断剧情进度，再查池中相应事件和人物，不能只对着条目标题猜剧情。碧翠丝与人神使用相同的线索流程。

## 它到底做什么

你写的世界书里藏着下一步该去哪、该见谁、该注意什么 —— 但正文模型不会主动去翻。这个扩展做三件事：

| | |
|---|---|
| **读线索** | 分批阅读选中世界书的全部非空条目内容，筛出剧情事件和登场人物建立线索池；每次引导先判断剧情进度，再找相关线索 |
| **给暗示** | 用一个**独立的辅助 API** 把这些线索转成一句铺垫式的暗示 —— **不会直接说「去某地」** |
| **吐槽** | 针对你刚才说的话、做的事，发表一句刻薄但心软的评论 |

结果以两种形式出现：悬浮窗里贝翠丝的气泡，以及正文结束后聊天气泡里的一条小字旁注。

### 引导长什么样

她**不会**说：

> ✗ 你该去旧城区打听消息。

她会说：

> ✓ 哼……今天街上的人都在往同一个方向走，真吵。贝蒂才不好奇他们去干什么。
> ✓ 刚才那个卖花的女人看了你三次。真是的，你要不要装作没发现，贝蒂可什么都没说。
> ✓ 空气里有股铁锈味，从昨晚就有了。……算了，跟你说了你也不懂。

具体手法写在提示词里（只给半个信息 / 用否定句引导 / 借别人的嘴 / 故意说一半就闭嘴 / 用情绪当路标），并带 ✗✓ 对照示例 —— 实测只写「不要直接指明」模型是听不懂的。

## 首次配置（3 步）

打开酒馆的 **扩展设置** → 找到 **🦋 碧翠丝的禁书库**。

### 1️⃣ 选辅助 API 通道

贝翠丝用的是**独立于正文的模型**，所以不能只靠「当前主连接」。

| 通道 | 说明 |
|---|---|
| **连接配置**（推荐，默认） | 复用你在酒馆「连接配置」里存好的 profile。**不用重复填 Key**，TauriTavern 一定支持。建议单独建一个便宜快速的配置给它 —— 它每 2 轮就要调一次。 |
| 酒馆助手 generateRaw | 功能最强（支持 JSON Schema 强约束），需要额外装 **JS-Slash-Runner**。 |
| 直连 OpenAI 兼容端点 | 自己填 URL / Key / Model，不依赖其它扩展。注意可能被 WebView 的域名策略拦截。 |
| 复用当前主连接 | 最省事，但会被当前预设污染。只作兜底。 |

配完点 **🧪 试说一句** 立刻验证 —— 它会真调一次 API 并把引导、吐槽、用到的线索全摊开给你看。

### 2️⃣ 勾选世界书（**不需要改任何东西**）

打开 **扩展设置 → 🦋 碧翠丝的禁书库 → 📖 世界书线索**（或点悬浮窗里的贝翠丝）。

**你不需要为了这个插件去改世界书。** 它会**自己读懂内容**，判断哪些条目是剧情条目。

**① 勾选要读哪几本世界书**

这里会列出酒馆里**所有**世界书，勾选你希望贝翠丝读取的那些。

> 早先版本要求条目带 `[引导]` 之类的标签 —— 那个前提是错的：
> 「没有写卡作者会为了我们的插件来特地制定剧情条目」。
> 现在默认读全部条目，由 AI 判断。

**② 让 AI 通读一遍**

点 **🔎 让 AI 通读世界书**。它会：

1. 读完你勾选的书（几百上千条也照读）—— **读的是条目正文，不是标题**
2. 给**每一条**写一行索引：这条讲什么、什么阶段才用得上
3. 顺便把**纯数值表**（属性、技能等级、判定公式）和**剧透性质的真相**排除掉

> 通读这一步**故意不淘汰条目**。原因：它读的时候**根本不知道剧情演到哪**，
> 而「这条有没有用」恰恰取决于你在第几章 ——
> 现在没用的条目，下一章可能正是最该用的那一条。
> 所以它只负责「编索引」，挑哪几条留给下一步（见下）。

> 判据是**正文**：标题经常毫无信息量（「设定补充」「杂项」），
> 而能用的钩子常常藏在正文里的一句话里。所以每条都会带上正文给 AI 看
> （长度可在「④ 高级」里调，默认 400 字）。

索引会存成一个「**线索池**」。

**③ 每轮生成时，先定位再取材**

正文写完那一刻，会多跑一次**很快**的请求（几百条索引也就一两秒）：

1. **先判断剧情演到哪** —— 把刚写完的正文连着上文一起给它读，
   它会说一句「刚到王都，还在街上闲逛，什么都还没发生」这类判断
2. **再从这个阶段的条目里挑出 3~5 条**，取回**原文**给贝翠丝用

> 这就是「**判断第几章 → 找对应章节的剧情**」这个思路的落地。
> 它挑出来的**条目名和判断结论**都会显示在设置里（🗂 线索池一栏的最上面），
> `/bg-status` 也能看到 —— 她要是挑偏了，你一眼就能发现是索引写得不对、
> 还是她读错了位置。

> 没被挑中的条目**不会消失**：它们仍以一句摘要的形式留在提示词里当兜底，
> 只是不会把全文白送进去（否则提示词会变胖好几倍）。
> 所以索引模式**不会再「丢掉」任何条目** —— 这是它跟早先设计最大的区别。

> **通读只做一次。** 索引缓存在本聊天里，之后每一轮只多跑一次「定位」。
> 作者改了世界书、或者你换了书单，它会自动重读。
> 定位这步可以关掉（「④ 高级」里选 `off`），关了就直接把整份索引当素材发下去。

> ⚠️ 第一次生成正文时它才开始通读（趁主模型写正文的时间），所以**最先一两轮
> 可能还没有索引**，建好之后就正常了。想立刻建好就手动点上面那个按钮。

**线索池：跟卡走、看得见、改得动**

它存在 `extensionSettings.characterHookPools[<角色卡>]` 里，**跟着角色卡走**：

- 换一张卡 → 各用各的池子，**不会串味**（这是刻意的：两张卡的世界观通常完全不同）
- 同一张卡换聊天线 → 池子还在，不用重新通读
- 关掉酒馆再打开 → 还在
- 作者改了世界书、或你换了书单 → 自动重读
- 超过有效期（默认 6 小时）→ 自动重读

想看 / 想改：设置里 **🗂 线索池** 那一栏（**独立一栏，不在世界书里面**）。

它会告诉你「绑定在哪张卡上、几条、什么时候建的、还能不能用」，然后把每一条都列出来：

| 能改什么 | 说明 |
|---|---|
| **标题** | 她说话时会用这个当线索名 |
| **正文** | 这一段才是真正喂给模型的素材 |
| **分类** | 线索 / 地点 / 事件 / 人物 / 征兆 / 设定 |
| **删掉** | AI 明显挑错的那条，直接移除 |
| **＋ 手工加一条** | AI 完全漏掉时自己补 |

> AI 判断一定会出错 —— 它可能把一条无关设定当线索，也可能把名字改得面目全非。
> 所以这一栏是**可编辑**的，不用整份重读（那会把好的也一起丢掉）。
>
> ⚠️ 改过之后有效期**从修改时间**重新算，不会被自动重读立刻冲掉。

> 想确认池子在不在：跑 `/bg-status`，或看 🧪 诊断页的 `hookPool` 字段：
> `{"count":7,"books":["..."],"character":"爱蜜莉雅","edited":false,"fresh":true}`
>
> ⚠️ 别被 `lastHooks` 骗了 —— 那个字段记的是「**上一次生成用了什么**」，
> 刚重启还没生成时它必然是空的，看起来像「没保存」，其实池子好好的。

**③ 或者自己挑（保底）**

AI 判断会漏 —— 它读不懂你的卡时可能一条都挑不出来。而且**你比任何模型都清楚**
自己书里哪条重要。所以：

点 **📋 列出条目让我自己挑** → 勾选你要的 → **✅ 用勾选的条目建立线索池**。

这条路**完全不需要 AI**（连辅助 API 都不用配），建出来的线索池和 AI 那条路
结构完全一样，引导照样用它。全自动之外留一条自己能掌控的路，是必要的。

**④ 只想排除剧透？用一个标签就够**

命中**排除标签**的条目无论 AI 怎么判断都不读。这不是筛选，是你主动声明的
「这块别碰」—— 比如给结局条目加上：

```
[禁止引导] 魔女教的真相        ← 绝不读
[剧透] 幕后黑手                ← 绝不读
旧城区的传言                   ← 什么都不用加，AI 会自己判断
连下了三天的雨                 ← 这条也会被挑中（征兆）
爱蜜莉雅人物设定               ← AI 会跳过（纯静态设定）
```

**⑤ 看看它读到了什么**

点 **🔍 看看会读到什么（不调 AI）** —— 直接列出进入候选的条目，配错了一眼就能看出来。

> 📄 `docs/example-worldbook.json` 是一份可以导入酒馆的**示例世界书**，
> 里面大部分条目**刻意不带标签**，用来演示「不用标签也能被挑中」。

### 3️⃣ 调出声节奏

默认「每 2 轮引导一次」，还有「按概率」和「每轮都说话」。另有最短间隔（默认 20 秒）防止你连点发送时她疯狂插嘴。

**觉得她太吵就调大 N**；想让她安静只吐槽不引导，把「引导」开关关掉即可。

### 设置：插件自己的窗口

**点悬浮窗里的贝翠丝就打开插件自己的设置窗** —— 不需要去酒馆的扩展设置里找。窗口左侧竖排七个标签页：

| 标签页 | 内容 |
|---|---|
| 🔌 **辅助 API** | 通道模式、连接配置、URL / Key、**🔄 拉取模型**、温度、超时，以及 **🔌 测试连接** |
| 🎯 **引导与吐槽** | 开关、字数上限、「只暗示不点名」约束、出声节奏、引导怎么呈现、**定位模式** |
| 📖 **世界书线索** | **勾选要读的世界书** + **🔎 让 AI 通读世界书（编索引）** + **📋 手动挑条目（保底）** + 排除标签 |
| 🗂 **线索池** | **她判断演到哪、挑了哪几条** + 逐条改摘要/阶段/分类 + 删掉 + 手工补一条 + 重读/清空 |
| 🪟 **外观** | 悬浮窗开关、**头像大小**、气泡时长与位置、待机动画、自定义立绘、重置位置 |
| 🧙 **人设** | **提示词编辑器**（分段，每条可选 SYSTEM / USER / ASSISTANT，可开关可调序） |
| 🧪 **诊断** | 复制诊断信息（**API Key 会自动打码**）、清空本聊天记忆、查看状态快照 |

每改一项**即时生效**，没有「保存」按钮。也可以随时用 `/bg-config` 打开它。

窗口底部有一行状态提示，一眼就能看出「现在能不能说话」：

> ✅ 通道已就绪 —— 点悬浮窗里的贝翠丝她就会说话。
> ⚠️ 还没选连接配置 —— 贝翠丝不知道用哪个模型说话

**设置只有这一个入口** —— 酒馆的「扩展设置」区里不挂任何东西。同一份设置有两个地方能改，除了让人疑惑「改哪个才生效」之外没有好处。

想打开设置窗的三种方式：

| 方式 | |
|---|---|
| 点悬浮窗里的贝翠丝 | 最直接 |
| `/bg-config` | 不想动鼠标时 |
| 控制台 `BeatriceGuide.config()` | 排查时 |

#### 🔄 拉取模型

填好 API 地址和 Key 后点它 —— 会去读那个端点的 `/models`，然后把模型填进**下拉框**，
你直接在列表里选就行（不用手打，也就不会打错大小写、`-preview` 后缀、中转别名）。
拉到的列表会存进设置，改别的选项不会把它清空。

拉不到也不影响（有些端点不提供 `/models`，或 Key 拿不到明文）：
在下拉框里选「（自定义…）」，会露出一个手填框。

#### 🔌 测试连接

点它真调一次 API，然后告诉你两件事：**连不连得上**，以及**模型有没有按格式返回**
（能看到引导、吐槽、情绪、用到的线索）。失败时给出常见原因。它不写入聊天记录，可以反复点。

### 人设：提示词编辑器

人设不再是「一整段大文本框」，而是**分段列表** —— 每段有自己的角色、开关和顺序：

```
#1  [SYSTEM   ▾]  ☑   ↑ ↓ 🗑
  你扮演「贝翠丝」。贝翠丝是一位寄居在契约者脑海里的契约精灵……
#2  [SYSTEM   ▾]  ☑   ↑ ↓ 🗑
  【性格】毒舌、傲娇、嘴硬心软……
#6  [ASSISTANT▾]  ☑   ↑ ↓ 🗑
  哼，知道了。贝蒂就说一两句，说多了你可别嫌烦。
```

好处很实际：**想让她这次少吐槽，把「吐槽规则」那条关掉就行**，不必在几千字里找。
换身份设定只改第 1 条。

- **内置默认**：首次打开就是这个状态。动任何一处会立刻转成你自己的副本，之后随便改
- **↺ 恢复内置人设**：一键回到出厂设定
- **📋 复制人设文本**：整段复制出来 —— 想让她在世界书里也有身份记录（让正文模型
  也认识她）时，新建一条世界书条目粘进去即可

**碧翠丝的默认身份是「寄居在契约者脑海里的契约精灵」**：她不是站在场外的旁观者，
而是住在他意识深处的存在 —— 他看不见她，但她看得见他看到的一切，听得到他心里没说出口的话。
这个设定顺带解释了她为什么能提起「他早该注意到却忽略了的细节」，也说明了她说的
为什么永远是**碎片**而不是完整的剧本。

### 内置提示词会自动升级

你打开过人设编辑器之后，那一份提示词就被存成了「你的配置」。
这带来一个隐蔽的问题：**我后来改进的提示词对你不再生效** —— 你看到的还是当初那版，
而且完全不知道为什么「更新了却没变化」。

现在内置提示词带了版本号，加载时会自动处理：

- 你**没手改过** → 自动换成新版（新加的规则段会一起进来）
- 你**改过**（无论改了多少）→ **一条都不动**，那是你的东西
- 想回到新版内置 → 人设页点 **↺ 恢复内置人设**

> 想确认自己看到的是哪一版：设置 → 🧪 诊断页会显示当前人设的来源与长度。

### 悬浮窗

- **拖**到任意位置，坐标自动记住；窗口缩小后会被自动拉回可视区内（不会「消失」）
- **点一下头像** → 打开插件自己的设置窗（唯一行为，不做状态分流）
- **大小可调**：设置 → 🪟 外观 → 「头像大小」滑块（48 ~ 256 px）
- **6 种情绪**（平静 / 得意 / 恼火 / 担心 / 微笑 / 思考）会切换配色与光晕
- 请求进行中显示「正在思考…」的三点动画
- 想让她立刻说一句：斜杠命令 `/bg-now`

> 随包立绘 `assets/beatrice.png` 是一张白底同人图**抠出来的**（`scripts/cutout.js`）。
> 抠图用的是「从图像边缘泛洪 + 填回内部小洞」而不是「白色一律透明」——
> 因为她身上本来就有大片白色（白裙、领口、高光），一刀切会把她挖成破洞的人。
> 重新抠图的流程：
> ```bash
> powershell -File scripts/decode-to-bmp.ps1 <你的图> assets/_source.bmp
> node scripts/cutout.js assets/_source.bmp assets/beatrice.png 12
> ```
> ⚠️ 容差**不要超过 12**：这张画风的脸色距纯白只有 23.4，容差到 16 就会把脸挖穿。
>
> ⚠️ 抠图脚本**只改 alpha、不动颜色**。早期版本为了让边缘的白边淡出而把边缘像素
> 「往暗处压」，结果整张图的平均色偏达到 ΔR=-4.4 ΔG=-6.3 ΔB=-6.2（线稿画风里
> 大部分像素都是描边，等于压了全身），用户一眼就看出颜色不对。

### 聊天里的旁注

默认把引导**接在正文末尾**，作为她突然插话的一段：

```
（这里是模型写的正文……）

──────────
贝翠丝：哼……今天街上的人都在往同一个方向走，真吵。贝蒂才不好奇他们去干什么。
```

与此同时，**吐槽**显示在悬浮窗的气泡里：

```
贝翠丝
一口气说能打三个？你连人家卖花的都打不过吧，笨蛋。
```

引导和吐槽是**同一次 API 调用**返回的两个字段（`guidance` / `commentary`），
分别去两个地方 —— 不会为了同一件事付两次钱，也不会出现「一次说往东、一次吐槽他往东」
这种自相矛盾。

> ### 为什么正文「看起来」被改了，其实没有
>
> 追加走的是**渲染层**：插件写的是 ST 的 `message.extra.display_text`，
> 酒馆渲染时用 `display_text ?? mes`。所以：
> - 屏幕上：正文里多了一段她的话
> - 数据里：`mes` 一个字节都没动
>
> 这样**重新生成、swipe、导出聊天、别的插件读到的**都还是干净的原始正文，
> 不会出现「多出来的那段删不掉」或者「swipe 之后重复两遍」这类问题。
> 重复触发也只会在原正文上重算，不会越接越长（有测试守着这条）。
>
> 不喜欢这种呈现方式的话，设置 → 🎯 引导与吐槽 → 「引导怎么呈现」可以切成
> **作为一条独立小字消息**（旧行为）或 **不写进聊天，只走气泡**。

## 它怎么工作（给好奇的人）

```
世界书（你勾选的那几本，不需要任何标签）
      │  ① AI 通读全书 → 给每条写一行索引（**不淘汰**）
      ▼
 线索池 = 索引（跟角色卡走，只建一次；每条只有一句摘要，不存正文）
      │  ② 正文写完 → 带着正文和上文判断「现在演到哪」→ 挑 3~5 条
      │  ③ 按 (书, 编号) 从世界书**实时取回原文**（作者改了立刻生效）
      ▼
  辅助 API（独立通道）──► { guidance, commentary, emotion }
      ▲                            │
 你的发言 + 刚写完的正文全文 ────────┘
                                   ▼
                    ┌──────────────┴──────────────┐
                    ▼                             ▼
             悬浮窗气泡（吐槽）            接在正文末尾（引导）
                    └──── 去重记忆（chatMetadata）◄────┘
```

**为什么通读不再淘汰条目。** 早先的设计让通读**直接挑出**「能用来推进剧情」的
条目（上限约 15%）。缺陷在用户一句话里被点破：

> 「那你就不能让读表 ai 读一下正文判断目前是第几章，
>   然后寻找对应章节的对应剧情给出提示吗」

通读的时候**完全不知道剧情演到哪**，而「这条有没有用」恰恰取决于你在第几章。
没被挑中的条目之后每一轮都看不到，**哪怕它正是这轮最该用的** ——
这个损失不可逆，是那套设计里唯一的硬伤。

现在通读只编索引（基本不淘汰），**定位**带着正文去检索。
代价是每轮多一次很快的 API 往返，换来的是**再也没有条目被永久丢掉**。

**为什么要分两步（还是分两步，只是切法变了）。** 通读整本书很贵（几十万字），
但「这本书里有什么」变化很慢（只有作者改书才会变）；「现在该用哪条」每轮都变，
但只需要读一份索引 + 一段正文。所以贵的那步只做一次，便宜的那步每轮做。

**调用时机改过一次，值得说明。** 现在是**正文写完之后**才调用（`generation_ended`）：

```
你点发送
   │
   ├─► GENERATION_AFTER_COMMANDS ──► 只做一件事：确保线索池可用
   │
   └─► 正文模型写正文 ──────────────► 通常 20~40 秒
                                        │
                          正文结束 ─────►┴─► 读完整的正文 → 调用 AI → 出声
```

早先的版本是「抢先式」：正文一开始生成就并发请求，等正文写完直接贴结果，
用户感觉不到等待。**但那个设计是错的** —— 辅助模型看不到刚生成的正文，
只能凭你上一句话和世界书猜，于是引导接不上剧情，用户看到的现象就是
「正文末尾没有引导」。

现在多等 1~5 秒，但那几秒有「碧翠丝正在观测…」状态条兜着，换来的是
**能真正接上刚写完那段剧情的引导**。这个取舍是用户提出来的，也是对的。

**去重**：她会记住自己说过什么（存在该聊天的 `chatMetadata` 里），用字符二元组 Jaccard 相似度挡住复读 —— 否则那几条线索会被翻来覆去讲几十轮。换聊天就是全新记忆。

## 四条设计原则

1. **不改正文。** 正文是你和正文模型的产物。她的话只写在渲染层（`display_text`），`mes` 一个字节都不动 —— 重新生成、swipe、导出都不会错位。
2. **不越权操纵剧情。** 旁注是隐藏的，不进正文模型上下文。往哪走由你决定。
3. **不要求你为它改变任何东西。** 不用给世界书加标签、不用改角色卡。它自己读懂内容，自己判断。
4. **失败必须安静。** 辅助 API 挂了、世界书读不到、连接超时 —— 都只是这一轮不出声，绝不会弹错误或卡住你的聊天。

### 她说话时的三条硬约束

引导的质量全靠这三条，它们写在人设提示词里（可以在设置里改）：

1. **接得上当前处境。** 自检方法写进了提示词：*如果这句话挪到另一个场景下也照样成立，那它就写坏了*。
2. **只给暗示，不点名目的地。** 带上 ✗/✓ 对照的例子 —— 实测只写「不要直接指明目的地」时模型仍然会写「去旧城区看看吧」。
3. **可以读线索，但必须改写。** 线索是**素材**，不是台词。不许复述原文；接不上就宁可只说一句状态观察，也不硬凑目的地。

## 排查

| 现象 | 先查什么 |
|---|---|
| **气泡里只有半句话**（比如「哼，光顾着发呆，旁边」） | 「最多输出 token」太小，JSON 被截断了。到 🩺 诊断页看有没有「输出被 token 上限截断」，调到 800~1500 |
| **正文末尾没有引导** | 先跑 `/bg-test` 看第 ④ 步。多半是「线索池为空」—— 到 📖 世界书线索页勾书并点「🔎 让 AI 通读」 |
| 通读说「没有可用的」 | 它现在会给出理由（例如「全是数值表」）。理由不对就用 📋 手动挑条目 |
| 通读只挑出很少几条（比如 1~2 条） | 偏少会让引导空泛。再点一次重挑（模型判断有随机性），或用 📋 自己挑 |
| **更新了插件但行为没变化** | ① 必须**重启酒馆**（扩展只在启动时加载一次）；② 人设提示词会自动升级，见下面一节 |
| 点头像没反应 | 跑 `/bg-test`，或看控制台。打开设置窗失败会弹提示并说明原因 |
| 完全不说话 | 设置面板底部**日志区**有没有 `[时间] 本轮不引导：…`（会写明原因：冷却中 / every-n 未命中 / 已引导过） |
| 说「没有线索」 | 点 **🔍 预览命中的线索**。一本书都没命中 → 条目没标标签；没关联世界书 → 到酒馆世界书面板把书挂到角色卡或全局勾选上 |
| 通道报错 | 点 **🧪 试说一句**，它会显示完整错误。`未选具体配置` → 到通道设置里选一个；401 → Key 不对 |
| 悬浮窗不见了 | 可能被拖到屏幕外了。执行 `/bg-config` 打开设置 → 外观 → 「↺ 重置悬浮窗位置」 |
| 想换人设 | 设置 → 🧙 人设 → 填自定义人设。⚠️ 填了会**整段替换**内置人设，记得把「只暗示、不点名目的地」那条规则自己写回去 |

**控制台调试入口**：`window.BeatriceGuide`

```js
BeatriceGuide.config()     // 打开插件设置窗
BeatriceGuide.state()      // 完整状态快照
BeatriceGuide.hooks()      // 预览命中的线索
BeatriceGuide.speak()      // 手动让她说一句
BeatriceGuide.settings()   // 当前生效的设置
```

诊断信息一键复制：设置 → 🧪 诊断与排查 → 📋 复制诊断信息。提 Issue 时贴这个。

## 开发

```bash
node scripts/check-syntax.js   # 加载检查：13 个模块 import 一遍 + manifest 校验
node test/run.js               # 单元测试（454 项）
node test/smoke-boot.js        # 装载冒烟测试（43 项，假 DOM 里真跑一轮完整对话）
npm run verify                 # 上面三个串起来
node _render/serve.js          # 浏览器渲染验收页（改 CSS 时用，见下）
```

> ⚠️ 如果你的 PowerShell 禁止运行 `npm.ps1`，用 `cmd /c "npm run verify"`。

### 看渲染效果：`_render/harness.html`

改 CSS 之后不必开酒馆 —— 这个验收页在真实浏览器里把插件加载起来，配一个假的酒馆上下文
和假的辅助 API，把「请求中 → 出声 → 换情绪」三个场景跑一遍。

```bash
node _render/serve.js 8791
# 浏览器打开 http://127.0.0.1:8791/_render/harness.html
```

> ⚠️ 必须走 http。直接双击打开 html 文件不行 —— 浏览器在 `file://` 协议下
> 出于 CORS 会拒绝动态 import 本地模块（`Failed to fetch dynamically imported module`）。

### 为什么不用 `node --test`

内置 runner 会为**每个测试文件 spawn 子进程**并通过管道收集输出。在受限环境（沙箱、某些 CI 容器）里
这个 spawn 会被直接拒绝（`spawn EPERM`），一个测试都跑不了。`test/run.js` 是同进程运行器，
API 与 `node:test` 保持一致 —— 想换回内置 runner 用 `npm run test:native`，测试代码一行都不用改。
