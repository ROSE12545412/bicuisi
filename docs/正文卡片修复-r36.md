# r36 正文卡片美化修复

## 原因

两种模式共用的显示判据只判断引导文字是否出现。宿主正常渲染 `extra.display_text` 后，正文尾部已有纯文字，修复函数因此跳过头像卡片，并主动删除已有卡片，导致样式存在但无法作用于正文。安装目录的样式、渲染模块及两个头像文件与开发目录哈希一致，资源缺失已排除。

## 修复目标

- 人神和碧翠丝都保留独立头像卡片；主题跟随每条引导生成时的 realm，不跟随当前模式强行改旧消息。
- 仅移除可确认属于插件的渲染尾段，避免纯文字与卡片重复；保留正文节点、格式、流式 iframe 和其他插件的覆盖。
- 不改变 mes，不请求 API，已有历史引导通过观察器恢复。

## 验证结果

- 813 项单元回归测试通过，64 项启动检查通过，22 个模块与 manifest 静态检查通过。
- 修复前浏览器可复现：宿主显示完整文本后，碧翠丝卡片消失。
- 修复后真实 Edge 模拟宿主 21 项检查通过，包含两种头像与主题、完整 display_text、格式化尾段、同句正文保留、iframe 身份、延迟覆盖恢复、编辑/切聊天/第三方覆盖。

## 验证边界

使用项目自带真实浏览器模拟宿主验证 DOM 与样式。此测试不等于已在用户真实酒馆及所有第三方格式化插件中完成兼容验证。
